## 5. Грабли, на которые я наступал (не повторяйте)

### 5.1 jsdom: `keydown` с кнопки не доходит до React

Измерено, не предположено: в `selection-dismissal` синтетический `keydown`, отправленный на
кнопку карточки, **не вызывает** ни `onKeyDown`, ни `onKeyDownCapture` трека. При этом:

- событие доходит до DOM-слушателя на треке (обычный `addEventListener` срабатывает);
- у кнопки есть `__reactFiber` / `__reactProps`, и волокно трека в цепочке выше действительно
  несёт `onKeyDown`;
- клики с того же узла доходят до React нормально;
- если отправить событие **прямо на трек** — обработчик вызывается и выделение снимается;
- window-слушатели событие получают.

Событие не доходит до React **вообще** (даже capture-фаза). Это ограничение среды. Обходной путь
в тестах: не изобретать хитрые способы доставки, а проверять наблюдаемое поведение через пути,
которые в jsdom работают, и оставлять Escape браузерному e2e.

Отдельная ловушка: **ссылка на DOM-узел устаревает после ре-рендера**. Если в тесте сохранить
кнопку до клика, а потом отправлять ей события — они не сработают. Перезапрашивайте узел после
каждого взаимодействия.

### 5.2 `git stash` здесь не работает

`git stash push --include-untracked` молча ничего не делает (только предупреждения CRLF), из-за
чего один мой «baseline»-прогон на самом деле содержал все правки сессии. Для baseline
используйте `git worktree` или явные копии файлов.

### 5.3 Многие тестовые файлы не отслеживаются git

27 untracked-записей, среди них новые тесты. `git checkout -- <file>` их **не восстановит** и,
что хуже, при наличии staged-версии может подменить содержимое. Проверяйте
`git cat-file -e HEAD:<path>` прежде чем полагаться на git как на источник истины.

### 5.4 Мои собственные ошибки инструментов

- **Кодмоды дважды молча испортили вывод** (мелодийные рецепты, импорты в тестах). Оба раза
  ловил `tsc` или прогон тестов, **ни разу** `eslint`.
- **PowerShell: `\t` и `\c` внутри двойных кавычек — управляющие символы.** Скрипт превратил
  `tonic:` в `<TAB>onic:`, а `activeModuleId` в `<BEL>ctiveModuleId` и испортил 5 файлов
  (18 ошибок синтаксиса). Escape-последовательности в шелл-строках пишите в одинарных кавычках.
- **Временные `*.mjs` в корне ломают `eslint`** (`no-undef` на `console`/`process`). Удаляйте
  их после использования; проверяйте `Get-ChildItem -Recurse | Where-Object Name -match '^(zz-|audit-|probe-)'`.
- `vitest` 5 **не имеет** флага `--reporter=basic`.
- **Экспорт константы из модуля с компонентом добавляет lint-предупреждение**
  (`react-refresh/only-export-components`) и ломает Fast Refresh для всего файла. Так вышло с
  `DEFAULT_VIEW_IDS`: пришлось вынести в `src/ui/common/defaultViewIds.ts`. Проверяйте
  `pnpm run lint` после добавления экспортов в `.tsx`.

### 5.5 Осторожно с «не работает»

Я записал неработающий `vitest` как непреодолимую границу окружения и **повторил это в десяти
раундах**. На деле `spawn` работает: первая попытка упала на моём же неверном флаге. «Не
работает» надо проверять так же строго, как «работает».

### 5.6 Флейки полного прогона

`vitest run --maxWorkers=1` иногда **молча пропускает файл** (наблюдалось: 189 файлов вместо 190,
`vexflow-adapter.test.ts` с 37 тестами не попал в прогон, при этом сводка показывала «всё
прошло»). В прошлом раунде видел и явный таймаут: `Failed to start forks worker ... Timeout
waiting for worker to respond`. **Сверяйте число файлов** с `Get-ChildItem tests -Recurse -Include
*.test.ts,*.test.tsx` (сейчас 190 без e2e). Если меньше — прогон неполный, перезапустите.

### 5.7 CRLF

`core.autocrlf=true`, поэтому файлы в checkout с CRLF, а Prettier ожидает LF. Часть файлов может
репортиться как неотформатированные просто из-за этого. `pnpm run format:check` сейчас чистый;
если он снова начнёт ругаться на файлы, которых вы не трогали, — это причина.

## 6. Как запускать

```bash
pnpm install --frozen-lockfile
npx vitest run --maxWorkers=1        # ~150–320 с, 190 файлов / 1377 тестов
pnpm run typecheck:tests             # 305 (отчётный)
pnpm run build                       # tsc -b && typecheck:layers && vite build
pnpm run lint
pnpm run format:check
pnpm run test:e2e:chromium           # Playwright, отдельный job в CI
```

CI: `.github/workflows/ci.yml` (блокирующие `build`, `typecheck:layers`, Prettier, `vitest run
--maxWorkers=1`, ESLint; отчётные `typecheck:tests` и `pnpm audit`; отдельный job Chromium e2e) и
`.github/workflows/deploy.yml` (гейтится успехом CI через `workflow_run`, чекаутит `head_sha`).
