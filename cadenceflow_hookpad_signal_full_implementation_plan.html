CadenceFlow · Hookpad + Signal Composition UX Program

Полный план развития композиционного редактора

Не копировать Hookpad или Signal буквально. Hookpad используется как источник композиционной UX-грамматики, Signal — как MIT-licensed технический донор зрелых direct-editing механик, а CadenceFlow остаётся владельцем harmony, exact timing, Project state, playback, notation и export.

Основной принцип Уменьшать расстояние между «вижу музыку» → «меняю музыку» → «слышу результат», не разрушая Harmonic Matrix, Staff, Inspector и каноническую domain-модель.
Граница программы Никаких AI-функций. Aria используется только как источник UX-паттернов. Signal используется только как источник/adaptable donor selection, drag, resize, clipboard, piano-roll и Web MIDI механик.

1. Hookpad + Signal + CadenceFlow: как именно соединять

Три системы полезны по разным причинам. Сильный вариант — не импортировать чужой продукт целиком, а разделить ответственность: Hookpad определяет композиционный UX, Signal помогает реализовать direct-editing mechanics, CadenceFlow остаётся каноническим музыкальным и проектным ядром.

Hookpad — UX grammar
  • Harmony + Melody на общей временной оси
  • scale-degree / harmonic-context presentation
  • direct manipulation рядом с музыкальным объектом
  • быстрое compositional sketching
  • beginner-friendly theory guidance
+
Signal — interaction mechanics
  • box/range selection
  • note drag и edge resize
  • multi-note move и Ctrl/Cmd-drag clone
  • clipboard / duplicate / quantize
  • Arrange View semantics
  • Web MIDI recording plumbing
→
CadenceFlow — canonical product
  • functional harmony + Matrix
  • strict routing / recommendations
  • exact Rational timing
  • Project + commands/history
  • Staff/Piano/Guitar/Tab
  • Audio + MIDI + MusicXML
Главная формулаHookpad отвечает на вопрос «как сочинение должно ощущаться», Signal — «как сделать selection/drag/resize надёжно», CadenceFlow — «что музыка означает и как она хранится».

3. Этап 0 — UX-контракт до разработки

До первого изменения кода зафиксировать правила, чтобы Hookpad-inspired улучшения не превратили CadenceFlow в piano roll и не создали вторую параллельную модель музыки.

Шесть правил

  1. Harmonic Matrix остаётся главным пространством harmonic exploration.
  2. My Progression становится главным пространством temporal composition/editing.
  3. Preview/Audition никогда не означает Commit.
  4. Timing использует только существующие MusicalDuration + exact Rational.
  5. Staff, Piano, Melody, MIDI, MusicXML и Audio не получают параллельных музыкальных моделей.
  6. Любая цветовая семантика обязана иметь нецветовой эквивалент.

Распределение ответственности

SurfaceГлавный вопрос
MatrixЧто я могу сыграть дальше?
My ProgressionЧто я уже сочинил и когда это звучит?
InspectorКак этот объект настроен глубоко?
Quick EditКак быстро поменять частое свойство?
StaffКак музыка читается как нотация?
Результат этапаНебольшой UX architecture document. Новые FR/SC добавляются только после утверждения архитектурной границы.

Самая важная несовместимостьSignal хранит timing как numeric MIDI ticks. CadenceFlow должен продолжать хранить exact Rational musical time. Signal-code используется только после отделения interaction mechanics от tick assumptions.

10. Обязательные acceptance gates

Каждый batch проходит одну и ту же цепочку проверки. Следующий batch не начинается до независимого ACCEPTED.

Code & correctness

Focused unit/integration tests, build, ESLint, Prettier, git diff --check.

Browser acceptance

Chromium --workers=1 --retries=0, 1280×720, 1920×1080, dark/light.

Interaction

Keyboard-only path, focus lifecycle, no page-level horizontal overflow.

Spec integrity

Проверка актуального spec.md до начала и отсутствие unintended spec changes.

History semantics

Одно пользовательское действие = одна history entry там, где действие атомарно.

Melody consistency

Для direct editing: Melody Lane = Staff = Playback = MIDI = MusicXML по pitch и exact timing.

Дополнительный gate для Signal-derived codeПроверить, что адаптированный код не тащит MobX/Jotai stores, MIDI-tick persistence, Signal snapshot history или скрытые assumptions о Track model. Pointer drag должен завершаться одним CadenceFlow command, а cancel — нулевой mutation.
