# T217 — панель Chord Properties

Статус: реализация авторизована пользователем 2026-10-08; этап A зафиксирован, этапы B–E в работе. Основание — запрос пользователя от 2026-10-07, предоставленный снимок компактной панели и явная авторизация полной реализации T217 от 2026-10-08.

## Цель и размещение

Предоставить компактное редактирование выбранного аккорда прогрессии в одной панели `Chord Properties`, используя существующий responsive Inspector. Первичная область — выбранный Chord Step в Piano Roll, Staff и Tablature. Панель показывает имя аккорда, функцию и фактические ноты; для Rest и отсутствия выбора музыкальные настройки недоступны с понятным пояснением.

Панель следует существующему выбранному аккорду, не создаёт отдельное скрытое выделение. На узком экране содержимое прокручивается без перекрытия музыки, нижней клавиатуры и status bar. Компоновка вдохновлена снимком; размеры и мелкий текст не копируются буквально.

Редактирование шаблонов Matrix — отдельный последующий этап переиспользования той же панели, с явной подписью контекста. Изменение выбранного Step не должно менять шаблон Matrix, соседние аккорды или всю прогрессию.

## Предлагаемый контракт интерфейса

1. **Type:** Triad / 7 / 9 / 11 / 13. Это состав аккорда, а не длительность. Качество основания и вид септимы должны быть явно показаны; C7 и Cmaj7 не объединяются в один неопределённый вариант. Переключение типа нормализует зависимые интервалы по документированным правилам.
2. **Inversion:** Root / 1st / 2nd / 3rd и доступные более высокие обращения по фактическому составу. Root означает основное положение; Auto, если требуется сохранить существующее наследование, отображается отдельно. Недоступные обращения отключены с пояснением. Семантический бас, например N6, учитывается явно.
3. **Options:** sus2/sus4, added tones, альтерации ♭/♯5, 9, 11, 13, omissions no3/no5. Нельзя одновременно включить sus2 и sus4 либо две противоположные альтерации одного интервала. `add9` отличается от 9 с септимой; аналогичные правила нужны для add11/add13. Несовместимые варианты не должны молча игнорироваться. Опцию `A-sub` из снимка не включать без определённого музыкального смысла и отдельного требования.
4. **Secondary:** None либо поддерживаемая secondary-функция и её цель. Первый набор — secondary dominant V/… и secondary diminished vii°/… с явным выбором целевой ступени. Обозначение, разрешение, корень и качество обновляются вместе. `IV/…` из снимка нельзя автоматически считать уже поддерживаемой функцией.
5. **Borrow From:** None и лад с той же тоникой: Ionian, Dorian, Phrygian, Lydian, Mixolydian, Aeolian, Locrian. Выбор заимствует аккорд соответствующей ступени выбранного лада, а не просто меняет подпись и не меняет тональность всей композиции. Сохраняется происхождение заимствования. Harmonic/Melodic Minor можно добавить отдельным расширением после определения правил.
6. **Reset:** восстанавливает гармонические свойства по исходной функции в текущем контексте одной Undo-командой; не сбрасывает длительность, Melody, инструменты и динамику. Конкретный baseline должен быть определён и показан подсказкой до реализации, без зависимости от случайно изменённого шаблона Matrix.

Переключатели применяют валидное изменение непосредственно к выбранному Step. Одно действие — одна Undo-команда; пустое изменение не добавляет историю. Панель не включает автоматически глобальное playback. Короткий preview может использовать существующее озвучивание аккорда; поздние audio completions отменяются при смене проекта/выбора. Для первого этапа — один аккорд, без неоднозначного массового изменения группы.

## Текущее состояние и пробелы

- `src/domain/harmony/chord.ts` содержит `HarmonicVariant`: seventh, extensions 9/11/13, suspensions, alterations, add9 и текущую валидацию. Модель не содержит явных no3/no5 и отдельных add11/add13.
- `src/domain/harmony/functions.ts` содержит secondary-dominant, secondary-diminished, modal-interchange и целевые функции. Это не подтверждает готовность произвольного Borrow From: нужно проверить генерацию, происхождение, переключение ладов и все проекции.
- Существующие Inspector/Quick Edit, команды прогрессии, обращения и bass metadata необходимо переиспользовать. Не создавать параллельный вычислитель аккордов только для панели.
- Расширение музыкальной модели должно одновременно покрыть runtime, portable codec/schema, migrations при необходимости, authored/generated Melody связи, voicing, Staff/TAB, MIDI и MusicXML. Один UI-checkbox без реализации звучащего состава недопустим.

## Этапы реализации

### A. Семантический контракт — зафиксирован

Составить таблицу всех настроек: существующее поле/команда, музыкальный результат, ограничения, влияние на бас и обращения, формат символа и экспорт. Зафиксировать правила Type, Secondary × Borrow, переключения качества и Reset. Для неподдержанной комбинации предпочтительнее явная недоступность с причиной, чем неявный fallback. Проверить существующие команды изменения Step и сохранение его ID, длительности, Melody, owner/instruments.

Результат: таблица выше reviewable; implementation choices зафиксированы до изменения музыкальной модели.

### B. Музыкальная модель

Добавить необходимые added-tone/omission и modal-origin данные минимально, сохраняя один канонический источник интервалов. Определить допустимые secondary/borrow сочетания; несовместимые варианты показываются до применения. Обновить все потребители атомарно. Если формат Project действительно меняется, отдельно обосновать и согласованно обновить schema/codec/factory/fixtures, не повышать версию одной константой.

Результат: unit-проверенные ноты, символы, бас и voicings для каждой опции; portable round-trip и точный Undo/Redo.

### C. Панель выбранного аккорда

Создать переиспользуемый компонент и подключить к текущему Step Inspector. Вынести в него существующие дублирующиеся настройки гармонии, оставляя длительность/динамику в их текущем контексте. Добавить segmented controls, доступные checkbox/select, объяснения отключённых вариантов и Reset. Значения берутся из канонического Project, без отдельной несинхронизированной копии аккорда.

Результат: компактная панель, работающая одинаково в трёх представлениях, без новых музыкальных вычислений внутри JSX.

### D. Secondary и Borrow From

Подключить проверенные преобразования гармонической функции и происхождение лада. Показать итоговые название, функцию и ноты до/после изменения. Изменение аккорда сохраняет Melody; проверить, что generated Melody пересчитывается согласно существующему контракту, а authored Melody не перезаписывается. Guitar voicing пересчитывается или явно сообщает отсутствие подходящей аппликатуры, без устаревшего изображения.

Результат: изменение слышимого и экспортируемого аккорда соответствует выбранным настройкам, а не только меткам.
